Complete Cybersecurity Roadmap

  1. Timeline

  1. Week 1: Networking Fundamentals
    Understand how computers communicate, IP addresses, protocols, ports, DNS, firewalls and VPNs.
  2. Week 2: Operating Systems
    Learn Linux, Windows, PowerShell, command line, permissions, system logs and Active Directory.
  3. Week 3: Cybersecurity Fundamentals
    Learn security concepts, encryption, authentication, access control and vulnerability management.
  4. Week 4: Ethical Hacking
    Learn reconnaissance, Nmap, Wireshark, Burp Suite, vulnerability scanning and web security in authorized labs.
  5. Week 5: Security Monitoring and SIEM
    Learn Splunk, Microsoft Sentinel, Elastic Security, log analysis and threat detection.
  6. Week 6: Incident Response and Digital Forensics
    Learn how to investigate, contain and respond to security incidents.
  7. Week 7: Security Automation
    Learn Python, Bash, PowerShell, log parsing, YARA and security automation.
  8. Week 8 and 9: Portfolio and Job Preparation
    Build four projects, practice security scenarios, prepare your resume and start applying.

Project 1: Network Traffic Analysis using Wireshark

Beginner

Network Security

Examine a captured packet using Wireshark | TechTarget

techtarget.com

Problem statement: Analyze network traffic to identify suspicious communication, unusual connections, DNS queries and potentially malicious activity.

Tools required:

  • Wireshark
  • TCP/IP fundamentals
  • Sample PCAP files
  • Python (optional)

Dataset / practice files:

Wireshark Official Sample Captures.

Step-by-step implementation

Step 1: Set up your environment

  • Install Wireshark.
  • Download sample PCAP files.
  • Open the packet capture.
  • Understand the packet list, packet details and packet bytes panels.

Step 2: Understand network traffic

Study:

  • Source and destination IP addresses.
  • Source and destination ports.
  • TCP and UDP protocols.
  • DNS queries.
  • HTTP and HTTPS traffic.
  • TCP handshakes.

Step 3: Apply Wireshark filters

Practice these filters:

Filter

Purpose

dns

Display DNS traffic

http

Display HTTP traffic

tcp

Display TCP packets

udp

Display UDP packets

icmp

Display ICMP traffic

tcp.flags.syn == 1

Identify SYN packets

ip.addr == 192.168.1.10

Filter traffic for an IP

dns.flags.rcode != 0

Identify DNS error responses

Step 4: Investigate suspicious activity

Look for:

  • Unusual outbound connections.
  • Repeated connection attempts.
  • Unexpected DNS queries.
  • Unusual traffic volume.
  • Suspicious communication patterns.

Don't label traffic malicious just because it looks unusual. Correlate it with context and other evidence.

Step 5: Create a Python analysis script

Use Python to:

  • Read exported packet information.
  • Count connections by IP.
  • Identify frequently contacted destinations.
  • Summarize protocol distribution.
  • Generate a simple report.

You can explore the Scapy library for more advanced packet processing.

Step 6: Prepare your final report

Include:

  • PCAP file source.
  • Network topology or traffic overview.
  • Protocol analysis.
  • Suspicious observations.
  • Supporting packet evidence.
  • Recommendations.

Project 2: SIEM Threat Detection Lab

Intermediate

Security Operations

Dashboard Studio: Schedule This! | Splunk

splunk.com

Problem statement: Build a Security Information and Event Management (SIEM) lab that collects system logs, detects suspicious activities and generates security alerts.

Tools required:

  • Splunk or Elastic Security
  • Windows Virtual Machine
  • Sysmon
  • Windows Event Logs
  • MITRE ATT&CK

Step-by-step implementation

Step 1: Set up your lab

Install:

  • Windows virtual machine.
  • Splunk Enterprise trial or an appropriate free learning environment.
  • Sysmon for collecting detailed Windows telemetry.

Use an isolated virtual machine and only generate test events in your own lab.

Step 2: Collect system logs

Collect:

  • Windows login events.
  • Failed authentication attempts.
  • Successful authentication events.
  • Process creation events.
  • System activity logs.

Useful Windows event IDs to understand:

Event ID

What it indicates

4624

Successful login

4625

Failed login

4688

4720

User account created

4726

User account deleted

1102

Security audit log cleared

Note: Event availability depends on Windows auditing configuration. Sysmon uses its own event IDs, so learn to distinguish the two.

Step 3: Send logs to SIEM

  • Configure log collection.
  • Connect your Windows lab machine.
  • Verify that events are being indexed.
  • Explore the incoming logs.
  • Understand timestamps, source, host and event fields.

Step 4: Create detection use cases

Build these three detection rules:

  1. Multiple failed login attempts from the same source.
  2. Unexpected user account creation.
  3. Suspicious process execution.

For example, a basic Splunk search for failed logins:

index=windows EventCode=4625

| stats count by Account_Name, Source_Network_Address

| where count >= 5

| sort - count

Adapt the index and field names to your actual log configuration.

Step 5: Map alerts to MITRE ATT&CK

For each detection:

  • Identify the suspicious behaviour.
  • Find the relevant ATT&CK tactic.
  • Identify the matching technique where applicable.
  • Document the evidence.

Step 6: Build a SIEM dashboard

Display:

  • Total login attempts.
  • Failed versus successful logins.
  • Suspicious user activity.
  • Top source IP addresses.
  • Security alerts by severity.
  • Incident timeline.

Step 7: Create an incident report

For every alert, document:

  • What happened?
  • When did it happen?
  • Which system was affected?
  • What evidence supports the alert?
  • What action should the security team take?

Project 3: Phishing Email Detection System

Intermediate

Python + Machine Learning

Subash Dahal – Software Engineer & Web Developer | Pokhara, Nepal

subashdahal17.com.np

Problem statement: Build a system that analyzes email content and predicts whether an email is legitimate or potentially phishing.

Tools required:

  • Python
  • Pandas
  • Scikit-learn
  • NLP basics
  • Streamlit
  • Jupyter Notebook

Dataset options:

  • Kaggle Phishing Email Dataset.
  • Apache SpamAssassin Public Email Corpus.

Check the dataset's labels and licensing before using it.

Step-by-step implementation

Step 1: Download the dataset

  • Download labelled email data.
  • Identify email text and classification labels.
  • Understand the difference between legitimate and phishing messages.
  • Check the number of records in each class.

Step 2: Clean the data

  • Handle missing email content.
  • Remove duplicates.
  • Normalize text.
  • Clean unnecessary HTML and formatting.
  • Inspect suspicious URLs and sender-related fields if provided.

Step 3: Perform text analysis

Understand:

  • Frequently occurring suspicious words.
  • Email length distribution.
  • URL patterns.
  • Sender-related patterns, if available.
  • Class distribution.

Step 4: Convert text into numerical features

Learn:

  • Bag of Words.
  • TF-IDF Vectorization.
  • N-grams.

For a beginner-friendly first version, use TF-IDF.

Step 5: Train classification models

Train and compare:

  • Naive Bayes
  • Logistic Regression
  • Random Forest
  • Linear SVM

Step 6: Evaluate the model

Use:

  • Precision
  • Recall
  • F1 Score
  • Confusion Matrix
  • ROC-AUC where appropriate

Pay special attention to false negatives, because missing a phishing email can be costly.

Step 7: Build a Streamlit application

Create an interface where users can:

  • Paste email content.
  • Submit the email for analysis.
  • View a phishing risk prediction.
  • See suspicious text patterns.
  • View the model's confidence or probability, properly calibrated if presented as a probability.

Add a clear disclaimer that this is a screening tool, not a guarantee that an email is safe.

Step 8: Deploy the application

Deploy your application using Streamlit Community Cloud or another suitable hosting service.

Final portfolio output

Phishing Email Detection Web App

Trained Classification Model

Model Evaluation Dashboard

Extra skill: Explain why your model flagged an email using interpretable text features. Don't claim that a message is definitely malicious based on a single keyword.

Project 4: Vulnerability Assessment Lab

Intermediate to Advanced

Penetration Testing

Acunetix vs Probely | Acunetix

acunetix.com

Problem statement: Create a controlled security testing environment, identify vulnerabilities, assess their severity and prepare a professional vulnerability assessment report.

Tools required:

  • Kali Linux
  • Nmap
  • OWASP Juice Shop
  • Burp Suite Community Edition
  • Greenbone/OpenVAS or Nessus Essentials, subject to current availability and licensing.

Step-by-step implementation

Step 1: Create your lab environment

Install:

  • Kali Linux virtual machine.
  • OWASP Juice Shop.
  • A separate isolated test network.

OWASP Juice Shop is intentionally vulnerable, so it is suitable for learning.

Dataset / lab link:

OWASP Juice Shop official project.

Step 2: Perform reconnaissance

Understand:

  • Target IP address.
  • Application architecture.
  • Exposed services.
  • Available web endpoints.
  • Technology information that can be safely identified.

Step 3: Perform network scanning

Use Nmap on your own lab machine.

Example:

nmap -sV -sC 192.168.56.101

This helps identify open ports, service versions and some common service information.

Step 4: Perform vulnerability assessment

Use a vulnerability scanner against your lab environment.

Identify:

  • Outdated software.
  • Misconfigurations.
  • Exposed services.
  • Missing security headers.
  • Known vulnerabilities where applicable.

Validate scanner findings rather than treating every scanner result as confirmed.

Step 5: Test web application security

Use Burp Suite and OWASP Juice Shop to understand:

  • SQL Injection.
  • Cross-Site Scripting.
  • Authentication weaknesses.
  • Broken access control.
  • Security misconfigurations.
  • Insecure application design.

Perform testing only inside your deliberately vulnerable lab.

Step 6: Prioritize vulnerabilities

Create a vulnerability register:

Use CVSS to assess severity, but don't confuse a CVSS score with the actual business risk.

Step 7: Prepare a professional report

Include:

  • Executive summary.
  • Scope of assessment.
  • Tools used.
  • Methodology.
  • Vulnerability details.
  • Evidence and screenshots.
  • Severity and risk ratings.
  • Recommended fixes.
  • Retest results.

Step 8: Remediate and retest

This is important.

Don't just find vulnerabilities. Fix the vulnerabilities in your lab and test again to verify that the issue is resolved.
